Ce guide fournit des comparaisons API côte-à-côte et des chemins de migration étape par étape pour les équipes passant de `flutter_query` ou `cached_query` à Qora.

---

## Depuis flutter_query

### Comparaison API

| Fonctionnalité | flutter_query | Qora |
| --- | --- | --- |
| Widget de requête | `QueryBuilder<T>` | `QoraBuilder<T>` |
| Requête infinie | `InfiniteQueryBuilder<T>` | `InfiniteQueryBuilder<T, TPageParam>` |
| Widget de mutation | `MutationBuilder<T>` | `QoraMutationBuilder<T, TVariables, TContext>` |
| Fournisseur de scope | `FlutterQueryClientProvider` | `QoraScope` |
| Client | `FlutterQueryClient` | `QoraClient` |
| Temps de cache | `cacheTime` | `gcTime` |
| Temps de péremption | `staleTime` | `staleTime` |
| Invalider | `client.invalidateQueries(['key'])` | `client.invalidate(['key'])` |
| Définir les données | `client.setQueryData(key, data)` | `client.setQueryData(key, data)` |
| Refetch au focus | `refetchOnWindowFocus` | `refetchOnWindowFocus` (via `FlutterLifecycleManager`) |
| Support hors-ligne | Non intégré | Intégré via `NetworkMode`, `FlutterConnectivityManager` |

### Différences Clés

**Modèle de cache.** flutter_query utilise une map plate clé-vers-données. Qora utilise des objets `CacheEntry<T>` qui contiennent à la fois le `QoraState<T>` courant et un stream broadcast: chaque abonné reçoit les transitions d'état instantanément.

**Gestion d'erreurs.** flutter_query expose les erreurs via le callback `error` de `QueryBuilder`. Qora utilise un `QoraState<T>` scellé avec correspondance de motifs: `Failure(:final error, :final previousData)` porte l'erreur et les données précédemment cachées pour une dégradation gracieuse.

**Hors-ligne.** Qora a un support hors-ligne intégré via `NetworkMode` et `ConnectivityManager`. Les requêtes peuvent se mettre en pause hors-ligne et rejouer à la reconnexion. flutter_query nécessite un câblage manuel pour le comportement hors-ligne.

### Migration Étape par Étape

**1. Remplacer le fournisseur de scope.**

```dart
// flutter_query
FlutterQueryClientProvider(
  client: client,
  child: MyApp(),
)

// Qora
QoraScope(
  client: client,
  child: const MyApp(),
)
```

**2. Remplacer les widgets de requête.**

```dart
// flutter_query
QueryBuilder<User>(
  queryKey: 'users',
  fetcher: () => api.getUser(),
  builder: (context) {
    if (context.isLoading) return const CircularProgressIndicator();
    if (context.hasError) return ErrorWidget(context.error.toString());
    return UserCard(context.data as User);
  },
)

// Qora
QoraBuilder<User>(
  queryKey: ['users'],
  fetcher: () => api.getUser(),
  builder: (context, state, fetchStatus) {
    return switch (state) {
      Success(:final data) => UserCard(data),
      Loading() => const CircularProgressIndicator(),
      Failure(:final error) => ErrorWidget(error.toString()),
      _ => const SizedBox.shrink(),
    };
  },
)
```

**3. Remplacer les widgets de mutation.**

```dart
// flutter_query
MutationBuilder<String, String>(
  mutator: (title) => api.createTodo(title),
  builder: (context, mutate) {
    return ElevatedButton(
      onPressed: context.isLoading ? null : () => mutate('New Todo'),
      child: const Text('Create'),
    );
  },
)

// Qora
QoraMutationBuilder<String, String, void>(
  mutator: (title) => api.createTodo(title),
  builder: (context, state, mutate) {
    return ElevatedButton(
      onPressed: state.isPending ? null : () => mutate('New Todo'),
      child: const Text('Create'),
    );
  },
)
```

**4. Remplacer les appels d'invalidation.**

```dart
// flutter_query
client.invalidateQueries(['users']);

// Qora
client.invalidate(['users']);
client.invalidateWhere((key) => key.firstOrNull == 'users');
```

**5. Mettre à jour le format des clés de requête.**

flutter_query utilise souvent des clés string. Qora utilise des clés `List<Object?>`:

```dart
// flutter_query
queryKey: 'users-$userId'

// Qora
queryKey: ['users', userId]
```

## Depuis cached_query

### Comparaison API

| Fonctionnalité | cached_query | Qora |
| --- | --- | --- |
| Création de requête | `Query<T>(fetcher: ...)` | `client.fetchQuery<T>(key: ..., fetcher: ...)` |
| Abonnement stream | `query.stream` | `client.watchState<T>(key)` |
| Invalidation | `query.refresh()` | `client.invalidate(key)` |
| Mutation | `Mutation<T>(mutator: ...)` | `client.mutate<T>(mutator: ...)` ou `QoraMutationBuilder` |
| Cache | Intégré, rafraîchissement manuel | Intégré, SWR avec revalidation automatique en arrière-plan |
| Pagination | Manuel via `Cubit`/`Bloc` | `InfiniteQueryObserver<T, TPageParam>` |
| File hors-ligne | Non intégrée | Intégrée via `OfflineMutationQueue` |

### Différences Clés

**SWR vs rafraîchissement manuel.** cached_query retourne la dernière valeur récupérée et nécessite un `query.refresh()` explicite pour refetcher. Qora utilise stale-while-revalidate (SWR): les données périmées sont retournées immédiatement, et un refetch en arrière-plan est déclenché automatiquement selon `staleTime`. Aucun appel manuel de refresh nécessaire.

**previousData.** Dans cached_query, un état de chargement jette la valeur précédente. Le `Loading<T>` de Qora porte `previousData` pour que l'UI puisse afficher les données périmées avec un indicateur de chargement au lieu d'un spinner plein écran.

**File de mutations hors-ligne.** Qora fournit une `OfflineMutationQueue` intégrée qui met en file les écritures hors-ligne et les rejoue à la reconnexion. cached_query nécessite une gestion hors-ligne manuelle.

**Modèle d'état.** cached_query utilise `AsyncValue` (loading/error/data). Qora utilise un `QoraState` scellé (Initial/Loading/Success/Failure) avec un axe orthogonal `FetchStatus` (fetching/paused/idle) pour la conscience réseau.

### Migration Étape par Étape

**1. Remplacer l'instanciation de requête.**

```dart
// cached_query
final query = Query<User>(
  fetcher: () => api.getUser(),
);
query.refresh();

// Qora
final client = QoraClient();
client.fetchQuery<User>(
  key: ['user'],
  fetcher: () => api.getUser(),
);
```

**2. Remplacer l'abonnement au stream.**

```dart
// cached_query
query.stream.listen((value) {
  // value est un AsyncValue<User>
});

// Qora
client.watchState<User>(['user']).listen((state) {
  // state est un QoraState<User>
  switch (state) {
    case Success(:final data): ...
    case Loading(): ...
    case Failure(:final error): ...
    case Initial(): ...
  }
});
```

**3. Remplacer le pattern de mutation.**

```dart
// cached_query
final mutation = Mutation<String>(
  mutator: (title) => api.createTodo(title),
);
await mutation.mutate('New Todo');

// Qora
await client.mutate<String>(
  mutator: () => api.createTodo('New Todo'),
  options: MutationOptions(invalidates: [['todos']]),
);
```

**4. Remplacer le refresh manuel par SWR.**

```dart
// cached_query: refresh manuel à chaque visite d'écran
onScreenEnter: () => query.refresh();

// Qora: revalidation automatique en arrière-plan basée sur staleTime
client.watchQuery<User>(
  key: ['user'],
  fetcher: () => api.getUser(),
  options: const QoraOptions(staleTime: Duration(minutes: 1)),
);
```

**5. Ajouter la file de mutations hors-ligne.**

La file hors-ligne de Qora ne nécessite aucun code supplémentaire avec `QoraMutationBuilder`:

```dart
// Aucune gestion hors-ligne manuelle nécessaire.
// Les mutations sont automatiquement mises en file hors-ligne et rejouées à la reconnexion.
QoraMutationBuilder<Todo, String, void>(
  mutator: (title) => api.createTodo(title),
  builder: (context, state, mutate) { ... },
)
```

## Patterns de Migration Communs

### Injection de Dépendances

Les deux librairies bénéficient d'un `QoraClient` unique fourni via `QoraScope`:

```dart [lib/main.dart]
void main() {
  final client = QoraClient(
    config: const QoraClientConfig(debugMode: kDebugMode),
  );

  runApp(
    QoraScope.auto(
      client: client,
      child: const MyApp(),
    ),
  );
}
```

### Normalisation des Clés de Requête

Qora normalise les clés en `List<dynamic>` en interne. Utilisez des structures de clés cohérentes:

```dart
// Liste paginée
['users', page]          // bon
'users-$page'            // à éviter

// Ressource imbriquée
['users', userId, 'posts']  // bon
'users/$userId/posts'       // à éviter
```

### Stratégie de Boundary d'Erreur

Enveloppez la gestion d'erreurs de l'app une seule fois via `QoraClientConfig.errorMapper` au lieu de blocs try/catch par requête:

```dart [lib/core/qora_setup.dart]
final client = QoraClient(
  config: QoraClientConfig(
    errorMapper: (error) {
      if (error is DioException) return AppError.fromDio(error);
      if (error is TimeoutException) return AppError.timeout();
      return error;
    },
  ),
);
```
