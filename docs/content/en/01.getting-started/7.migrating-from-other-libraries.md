This guide provides side-by-side API comparisons and step-by-step migration paths for teams moving from `flutter_query` or `cached_query` to Qora.

---

## From flutter_query

### API Comparison

| Feature | flutter_query | Qora |
| --- | --- | --- |
| Query widget | `QueryBuilder<T>` | `QoraBuilder<T>` |
| Infinite query | `InfiniteQueryBuilder<T>` | `InfiniteQueryBuilder<T, TPageParam>` |
| Mutation widget | `MutationBuilder<T>` | `QoraMutationBuilder<T, TVariables, TContext>` |
| Scope provider | `FlutterQueryClientProvider` | `QoraScope` |
| Client | `FlutterQueryClient` | `QoraClient` |
| Cache time | `cacheTime` | `gcTime` |
| Stale time | `staleTime` | `staleTime` |
| Invalidate | `client.invalidateQueries(['key'])` | `client.invalidate(['key'])` |
| Set query data | `client.setQueryData(key, data)` | `client.setQueryData(key, data)` |
| Refetch on focus | `refetchOnWindowFocus` | `refetchOnWindowFocus` (via `FlutterLifecycleManager`) |
| Offline support | Not built-in | Built-in via `NetworkMode`, `FlutterConnectivityManager` |

### Key Differences

**Cache model.** flutter_query uses a flat key-to-data map. Qora uses `CacheEntry<T>` objects that hold both the current `QoraState<T>` and a broadcast stream: every subscriber receives state transitions instantly.

**Error handling.** flutter_query exposes errors via `QueryBuilder`'s `error` callback. Qora uses a sealed `QoraState<T>` with pattern matching: `Failure(:final error, :final previousData)` carries the error and any previously cached data for graceful degradation.

**Offline.** Qora has built-in offline support via `NetworkMode` and `ConnectivityManager`. Queries can pause when offline and replay on reconnect. flutter_query requires manual wiring for offline behavior.

### Step-by-Step Migration

**1. Replace scope provider.**

```dart
// flutter_query
FlutterQueryClientProvider(
  client: client,
  child: MyApp(),
)

// Qora
QoraScope(
  client: client,
  child: const MyApp(),
)
```

**2. Replace query widgets.**

```dart
// flutter_query
QueryBuilder<User>(
  queryKey: 'users',
  fetcher: () => api.getUser(),
  builder: (context) {
    if (context.isLoading) return const CircularProgressIndicator();
    if (context.hasError) return ErrorWidget(context.error.toString());
    return UserCard(context.data as User);
  },
)

// Qora
QoraBuilder<User>(
  queryKey: ['users'],
  fetcher: () => api.getUser(),
  builder: (context, state, fetchStatus) {
    return switch (state) {
      Success(:final data) => UserCard(data),
      Loading() => const CircularProgressIndicator(),
      Failure(:final error) => ErrorWidget(error.toString()),
      _ => const SizedBox.shrink(),
    };
  },
)
```

**3. Replace mutation widgets.**

```dart
// flutter_query
MutationBuilder<String, String>(
  mutator: (title) => api.createTodo(title),
  builder: (context, mutate) {
    return ElevatedButton(
      onPressed: context.isLoading ? null : () => mutate('New Todo'),
      child: const Text('Create'),
    );
  },
)

// Qora
QoraMutationBuilder<String, String, void>(
  mutator: (title) => api.createTodo(title),
  builder: (context, state, mutate) {
    return ElevatedButton(
      onPressed: state.isPending ? null : () => mutate('New Todo'),
      child: const Text('Create'),
    );
  },
)
```

**4. Replace invalidation calls.**

```dart
// flutter_query
client.invalidateQueries(['users']);

// Qora
client.invalidate(['users']);
client.invalidateWhere((key) => key.firstOrNull == 'users');
```

**5. Update query key format.**

flutter_query often uses string keys. Qora uses `List<Object?>` keys:

```dart
// flutter_query
queryKey: 'users-$userId'

// Qora
queryKey: ['users', userId]
```

## From cached_query

### API Comparison

| Feature | cached_query | Qora |
| --- | --- | --- |
| Query creation | `Query<T>(fetcher: ...)` | `client.fetchQuery<T>(key: ..., fetcher: ...)` |
| Stream subscription | `query.stream` | `client.watchState<T>(key)` |
| Invalidation | `query.refresh()` | `client.invalidate(key)` |
| Mutation | `Mutation<T>(mutator: ...)` | `client.mutate<T>(mutator: ...)` or `QoraMutationBuilder` |
| Caching | Built-in, manual refresh | Built-in, SWR with automatic background revalidation |
| Pagination | Manual via `Cubit`/`Bloc` | `InfiniteQueryObserver<T, TPageParam>` |
| Offline queue | Not built-in | Built-in via `OfflineMutationQueue` |

### Key Differences

**SWR vs manual refresh.** cached_query returns the last fetched value and requires explicit `query.refresh()` to fetch again. Qora uses stale-while-revalidate (SWR): stale data is returned immediately, and a background refetch is triggered automatically based on `staleTime`. No manual refresh calls needed.

**previousData.** In cached_query, a loading state discards the previous value. Qora's `Loading<T>` carries `previousData` so the UI can display stale data with a loading indicator instead of a full-screen spinner.

**Offline mutation queue.** Qora provides a built-in `OfflineMutationQueue` that queues writes when offline and replays them on reconnect. cached_query requires manual offline handling.

**State model.** cached_query uses `AsyncValue` (loading/error/data). Qora uses a sealed `QoraState` (Initial/Loading/Success/Failure) with an orthogonal `FetchStatus` axis (fetching/paused/idle) for network awareness.

### Step-by-Step Migration

**1. Replace query instantiation.**

```dart
// cached_query
final query = Query<User>(
  fetcher: () => api.getUser(),
);
query.refresh();

// Qora
final client = QoraClient();
client.fetchQuery<User>(
  key: ['user'],
  fetcher: () => api.getUser(),
);
```

**2. Replace stream subscription.**

```dart
// cached_query
query.stream.listen((value) {
  // value is an AsyncValue<User>
});

// Qora
client.watchState<User>(['user']).listen((state) {
  // state is a QoraState<User>
  switch (state) {
    case Success(:final data): ...
    case Loading(): ...
    case Failure(:final error): ...
    case Initial(): ...
  }
});
```

**3. Replace mutation pattern.**

```dart
// cached_query
final mutation = Mutation<String>(
  mutator: (title) => api.createTodo(title),
);
await mutation.mutate('New Todo');

// Qora
await client.mutate<String>(
  mutator: () => api.createTodo('New Todo'),
  options: MutationOptions(invalidates: [['todos']]),
);
```

**4. Replace manual refresh with SWR.**

```dart
// cached_query: manual refresh on every screen visit
onScreenEnter: () => query.refresh();

// Qora: automatic background revalidation based on staleTime
client.watchQuery<User>(
  key: ['user'],
  fetcher: () => api.getUser(),
  options: const QoraOptions(staleTime: Duration(minutes: 1)),
);
```

**5. Add offline mutation queue.**

Qora's offline queue requires no extra code when using `QoraMutationBuilder`:

```dart
// No manual offline handling needed.
// Mutations are automatically queued when offline and replayed on reconnect.
QoraMutationBuilder<Todo, String, void>(
  mutator: (title) => api.createTodo(title),
  builder: (context, state, mutate) { ... },
)
```

## Shared Migration Patterns

### Dependency Injection

Both libraries benefit from providing a single `QoraClient` via `QoraScope`:

```dart [lib/main.dart]
void main() {
  final client = QoraClient(
    config: const QoraClientConfig(debugMode: kDebugMode),
  );

  runApp(
    QoraScope.auto(
      client: client,
      child: const MyApp(),
    ),
  );
}
```

### Query Key Normalization

Qora normalizes keys to `List<dynamic>` internally. Use consistent key structures:

```dart
// Page-indexed list
['users', page]          // good
'users-$page'            // avoid

// Nested resource
['users', userId, 'posts']  // good
'users/$userId/posts'       // avoid
```

### Error Boundary Strategy

Wrap your app's error handling once via `QoraClientConfig.errorMapper` instead of per-query try/catch blocks:

```dart [lib/core/qora_setup.dart]
final client = QoraClient(
  config: QoraClientConfig(
    errorMapper: (error) {
      if (error is DioException) return AppError.fromDio(error);
      if (error is TimeoutException) return AppError.timeout();
      return error;
    },
  ),
);
```
