Qora's debugging tool is the **in-app overlay**: a panel rendered inside your running app, in debug builds only. It shows each query's status and data, every mutation with its variables and result, and the calls waiting in the mutation queue, as it happens.

Install it, wrap the app with `QoraInspector`, and tap the **Q** button. Works on simulators, emulators and physical devices.
::

## What you can see and do

| Area | Contents |
| ---- | -------- |
| **Queries** | Every key with its status (fetching, success, error, stale, idle), searchable. The inspector shows the data and the options of the last fetch, with actions: Invalidate, Remove, Mark Stale, Simulate Error |
| **Mutations** | Pending and settled mutations, with their variables, result or error, and duration |
| **Queue** | The calls waiting in `client.mutationQueue`: status, attempts, scope, last error and variables. Read only |
| **Timeline** | Fetches, cancellations, invalidations, `setQueryData` writes, mutations and cache clears, in order |

The query actions and the Queue tab require passing the client to `QoraInspector`.

## How it works

`QoraClient` reports what it does to a `QoraTracker`. The overlay provides one, `OverlayTracker`, which keeps the recent events in memory (200 per channel) for the panel to display.

```text
QoraClient
    │
    ├── NoOpTracker     default, and in release: no events, no cost
    └── OverlayTracker  debug builds: events kept in memory for the panel
```

In release builds you pass `null` as the tracker, so the client uses `NoOpTracker`, and `QoraInspector` builds nothing. See [Production safety](./overlay.md#production-safety).

To send the same events to more than one tracker (the overlay and your own logging, for example), combine them with `MultiTracker` from `qora`.
