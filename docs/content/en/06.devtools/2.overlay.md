## Installation

```bash [Terminal]
flutter pub add qora_devtools_overlay
```

Add it to `dependencies`, not `dev_dependencies`: your `main.dart` imports it, and importing a dev dependency from `lib/` is flagged by the `depend_on_referenced_packages` lint. It does not cost anything in release, as explained in [Production safety](#production-safety).

## Setup

Create an `OverlayTracker` and pass it to both `QoraClient` and `QoraInspector`. Pass the client reference to `QoraInspector` to enable the query actions and the Queue tab.

```dart [main.dart]
import 'package:flutter/foundation.dart';
import 'package:flutter/material.dart';
import 'package:qora_devtools_overlay/qora_devtools_overlay.dart';
import 'package:qora_flutter/qora_flutter.dart';

void main() {
  final tracker = OverlayTracker();

  final client = QoraClient(
    // null in release mode: QoraClient uses NoOpTracker, no events emitted.
    tracker: kDebugMode ? tracker : null,
  );

  runApp(
    QoraInspector(
      tracker: tracker,
      // Enables the query actions (Invalidate, Remove, ...) and the Queue
      // tab. Without it, actions are hidden and the Queue tab says how to
      // enable it.
      client: kDebugMode ? client : null,
      child: QoraScope.auto(client: client, child: const MyApp()),
    ),
  );
}
```

In debug mode, a **Q** button is rendered in the bottom-right corner of the screen. Tapping it opens the panel.

::callout{type="warning"}
The `client` parameter is optional. Without it, `QoraInspector` is a read-only observer: the **ACTIONS** section is not rendered, and the **Queue** tab explains how to enable it.
::

::callout{type="info"}
`QoraInspector` renders nothing in release builds. The guard is applied at widget level: the overlay subtree is not constructed when `kDebugMode` is false.
::

## Mutation queue

The **Queue** tab lists the calls waiting in `client.mutationQueue`: registered mutations called with `offlineQueue: true` (see [Offline & Network](/en/core-concepts/offline)). It reads the queue itself, so it also shows calls restored by `PersistQoraClient.hydrate()` at startup.

| Column | Meaning |
| ------ | ------- |
| Status | `queued`, `sending`, `blocked` (failed for good at the head of its scope), `held` (behind a blocked call), `failed` (failed for good, no scope) |
| Attempts | Attempts since the call was queued or last retried |
| Scope | The scope returned by the registration, or none |

Selecting a call shows its `mutationId`, its last error and its variables. The tab is read only: retrying or discarding a call is a decision of the app, through `mutationQueue.retry` and `mutationQueue.discard`.

---

## Known limits

The query list is built from the events the client sends to the tracker, not read from the cache. Two writes send no event, so they create no row until the query is fetched: data restored by `PersistQoraClient.hydrate()` and `initialData`.

## Responsive behavior

The overlay layout adapts to the available screen width.

- **600 px and above** (tablet, desktop): three-column layout with all panels visible simultaneously.
- **Below 600 px** (phone): single-column navigation with forward navigation into inspector and timeline views.

## Production safety

Two independent mechanisms keep the overlay out of production:

### 1. Compile-time guard

```dart
@override
Widget build(BuildContext context) {
  if (!kDebugMode) return child; // nothing is built in release
  return _buildOverlay();
}
```

`kDebugMode` is a compile-time constant. In a release build the overlay branch is unreachable, and tree shaking removes the panel's code.

### 2. NoOpTracker in release

`QoraClient` is constructed with `tracker: kDebugMode ? tracker : null`. In release mode, `null` activates `NoOpTracker`. Its methods are no-ops and no tracking events are emitted.

Result: no runtime impact from the overlay tracker path in production.
